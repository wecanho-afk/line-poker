# W 撲克

Node.js 20+：`npm ci`，再執行 `npm start`（預設 port 5000）。`node server.js` 與 `npm start` 使用相同引擎。執行 `npm test` 驗證核心規則。

## 玩家、回顧與練習

- 新增機器人時抽取五種現場風格：休閒跟注、謹慎被動、穩健常客、鬆兇施壓、緊手價值型。權重是產品模擬預設，並非現場人口統計。每人再抽取固定的鬆緊、侵略性、詐唬率與尺寸差異。
- 決策只使用自己的牌及公開狀態，依位置、底池賠率、籌碼與人數調整；沒有讀取其他人的底牌或未發出的牌。
- 「手牌回顧」在此瀏覽器的 IndexedDB 保存最近 100 手，逐步顯示行動前牌面、底池、籌碼、實際動作和你的策略建議。只在結束後提供分析，棄牌也會記錄，未亮出的對手牌不會出現在回顧。重新整理或回顧 API 暫時離線時仍可讀取本地紀錄。
- 「場景練習」提供 24 個場景，可依翻牌前、翻牌、轉牌、河牌與短碼篩選：包括盲注防守、3-bet／4-bet、200BB 小口袋對、check-raise、組合聽牌、單色牌面、轉牌二次施壓、河牌薄價值／超池下注／阻擋牌，以及 10–15BB 短碼。從題目狀態進入真正牌局，打完後可回顧或重練。
- 深色響應式牌桌顯示手數、盲注、底池、對手風格與可用動作。快捷下注先填金額，按「加注」送出。

## 分析的限制

策略使用確定性的 96 次未知牌抽樣和啟發式規則；它不是 GTO solver。翻牌前對手範圍依公開下注篩選；翻牌後使用寬範圍，尚未完整建模每條下注線，因此對強烈價值線可能高估勝率。結果不保證是數學上的最佳動作，未計抽水、ICM、完整下注樹或精確 EV；場景解析提供额外的概念指引。

## 手牌保存及部署

牌局以 Socket.IO 即時推送，並每秒使用 HTTP 備援同步。同步請求會執行已到期但尚未執行的電腦動作、全下發牌與結算，避免背景計時器暫停時停在上一個畫面；動作先取出再執行，防止重複處理。HTTP 同步失敗會顯示連線狀態；牌局已不存在時返回大廳。這不取代下述持久儲存與常駐後端要求。

完成的手牌透過該玩家專屬狀態傳給瀏覽器，以 IndexedDB 交易保存與去重，最多 100 手。伺服器即使磁碟唯讀，仍會回傳自己的完整回顧，並在程序記憶體保留短期備援。UI 只有在瀏覽器交易完成後才顯示已儲存，儲存空間遭拒絕時會提示。

伺服器也會嘗試寫入 `POKER_HISTORY_DIR`（預設 `.data/hands`），若需要伺服器備份，請掛載持久磁碟。此檔案備份仍適用單一 Node 程序，不支援多副本競爭寫入。牌局本身仍保存在記憶體，伺服器重啟後不會續局。

瀏覽器保存隨機回顧金鑰；回顧 API、既有座位操作與 Socket 座位訂閱會驗證金鑰。金鑰不會出現在牌局 JSON。請使用同一瀏覽器與帳號回顧，清除網站資料會刪除本地紀錄，不提供跨裝置同步。這是座位憑證，並不等同於 LINE access token 的伺服器端身分驗證。

請以常駐 Node 伺服器提供多人遊戲（含 Socket.IO）。保留的 Vercel 路由已指向相同 API，但 Vercel 的短生命週期函式不適合此記憶體牌局、長連線與本機手牌保存架構；若使用 Vercel，仍需另接常駐遊戲後端與持久儲存。此修改沒有部署或更動線上服務。
